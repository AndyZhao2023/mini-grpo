# M0 data flow and representation contract

Notation: `B` is prompts per rollout batch (one in the current runner), `G=4` is responses per prompt, `P` is prompt-token length, and `T` is generated-token length (up to 256 in the end-to-end training config). Variable lengths are padded only in memory. A JSONL line stores one trajectory with native Python/JSON scalar and list types; it never stores a tensor or a device handle.

```text
GSM8K train question + stable row ID [B] (CPU)
  → fixed system/user chat template → prompt token IDs [B,P] (CPU → MPS)
  → policy rollout → response IDs [B,G,T], EOS/length status (MPS → CPU)
  → raw policy forward before update → old_log_probs [B,G,T] (MPS → CPU)
  → deterministic answer verifier → reward and reason [B,G] (CPU)
  → group normalization → advantage [B,G] (CPU or MPS)
  → broadcast advantage over valid response tokens [B,G,T] (MPS)
  → clipped GRPO loss → gradient → optimizer step (MPS)
  → next rollout with incremented policy_version
```

| Artifact | Producer | Consumer | Storage and checks |
| --- | --- | --- | --- |
| Question, ID, prompt text | GSM8K loader and chat template | Rollout, verifier, JSONL | CPU; prompt excludes reference answer |
| `prompt_token_ids` | Tokenizer | Generator and log-prob forward | CPU JSONL; move to MPS for model calls |
| `response_token_ids`, `response_mask`, `finish_reason` | Rollout | Old-policy forward, loss, JSONL | CPU JSONL; EOS is a valid generated token; padding is masked out |
| `old_log_probs` | Raw model logits, no grad, **before** any step | Ratio and diagnostics | One value per response ID; detached CPU JSONL; regenerated for each policy version |
| `reward`, `reward_reason` | Deterministic verifier | Group normalization, diagnostics | CPU JSONL; complete after verification |
| `advantage` | Population mean/std over each full group | Every valid token in its response | CPU JSONL; all-equal reward group gets exactly zero |
| `policy_version`, model/tokenizer revisions | Trainer and config | Group validation, reproducibility | Text; every response in a group shares one version. `model_revision` is the upstream initial snapshot; `policy_version` and the local checkpoint identify later trained weights. |

`Trajectory` allows `old_log_probs`, `reward`, and `advantage` to be absent while a rollout is being assembled. A complete training group must have all three before an update. `validate_group(..., require_complete=True)` enforces this boundary. The JSONL writer validates each row; the reader reports malformed line numbers. `response_mask` is a prefix of ones followed by zeros, so it can represent EOS, length truncation, and padding without assigning loss to pad IDs.

The first real rollout slice is in `src/rollout/hf_rollout.py`. After sampling, it trims each output at the first tokenizer EOS and recomputes `old_log_probs` using a separate no-grad forward with the same unchanged model. For a prompt of P tokens, raw logits at index `P-1+t` score generated response token `t`; `generate()` scores are not used. Stored examples omit padding after EOS, so their response masks are all ones. The four records in `results/m0/rollout-sample.jsonl` have the same `policy_version` and leave reward and advantage null.

`src/reward/math_verifier.py` reads only a complete `#### <number>` on the last nonblank line of each response. It compares that number to the pinned GSM8K reference with exact decimal arithmetic. Missing or malformed lines, wrong numbers, and correct numbers have distinct reason codes. `scripts/score_rollout.py` checks that the group belongs to the pinned training partition, then writes a separate `results/m0/rewarded-sample.jsonl`. The current four responses all lack the required final line, so each has reward 0 and reason `missing_final_answer`.

`src/grpo/advantage.py` computes one scalar per response from the full group: `A_i = (r_i - mean(r)) / (population_std(r) + 1e-8)`, with exact zero for every member of an all-equal group. `scripts/normalize_advantages.py` reads the scored CPU JSONL and writes `results/m0/advantaged-sample.jsonl`; the original scored artifact is preserved. It validates the full group and all training-required fields, including `old_log_probs`. The current sample has four zero rewards, so its four advantages are exactly zero and the zero-variance diagnostic is true.

`src/grpo/loss.py` packs a complete JSONL group into tensors on the configured device: model `input_ids` are `[G,P+T]`, while old log probabilities and the boolean response mask are `[1,G,T]`. Prompt tokens participate in the model forward for context but have no loss positions. Generated EOS has mask 1; right padding has mask 0. `scripts/check_grpo_loss.py` uses the pinned model's raw logits to compute new response log probabilities, then sets `ratio = exp(new-old)` on valid tokens. The clipped surrogate is averaged over valid tokens per response, then over responses within the group and groups in the batch; `beta=0` means no reference-KL penalty. `clip_fraction` counts valid tokens with ratio outside `[0.8,1.2]`, and `approx_kl_old` is the valid-token mean of `(ratio-1)-log(ratio)` for the current policy relative to the rollout policy. The script runs without gradients or an optimizer step. The saved `results/m0/loss-smoke.json` has 193 valid tokens, ratio exactly 1 before an update, and zero loss because this group's advantages are all zero. The later mixed-reward smoke step is described below.

`scripts/find_trainable_group.py` scans a bounded number of pinned training prompts and records reward vectors, parse-failure counts, response lengths, and `zero_std_group_fraction`. Original and shortest-question orders are explicit; shortest uses question text and prompt ID, never reference answers. It saves complete rollout/scored/advantaged JSONL only for the first mixed-reward group. The original-order and shortest-first 64-prompt scans, plus two 16-prompt format pilots, all had zero strictly correct responses and no selected group. A versioned prompt with one independent formatting example selected a mixed-reward training group after seven shortest-first questions; its reward vector is `[0, 0, 1, 0]` and its four complete JSONL trajectories are in `results/m0/format-example/`. `src/grpo/trainer.py` and `scripts/train_grpo_smoke.py` then ran one guarded full-parameter AdamW update with the saved rollout `old_log_probs`: the trainer required pre-update ratio near one and a nonzero finite gradient, then measured post-update drift. The script checked pinned data, prompt tokens, rewards, and advantages before loading the model and saved a local checkpoint under Git-ignored `results/m0/format-example/checkpoints/`. The checkpoint excludes optimizer state. The observed post-update `approx_kl_old=0.1914` and clip fraction `0.2199` call for learning-rate calibration before repeated updates. Tiny-model CPU tests independently verify trainer mechanics.

The Day 1 model smoke uses two fixed arithmetic prompts, not GSM8K rows. Its backward pass establishes that the pinned model can generate and propagate gradients on this machine. It does not verify `old_log_probs`, reward, or the GRPO loss; those are Day 2–3 checks.

The train/internal-validation split is fixed from GSM8K `train` with seed 42 and 200 held-out questions. `src/data/dataset.py` loads only the pinned train parquet, preferring the exact revision's local cache, verifies the row count and content digest, and assigns original-row IDs before selecting validation positions by SHA-256 rank of `seed:index`. `build_prompt_messages` consumes only the question and system instruction; the reference answer is read separately by the verifier. `results/m0/dataset-split.json` records the selected IDs and two answer-free prompt previews. The official `test` split is run only in the final report. Evaluation uses greedy decoding and `max_new_tokens=128`; training reward is diagnostic and is not substituted for held-out pass@1.

`scripts/run_m0.py` is the current single CLI entry. It loads the split once, saves the manifest, then calls `src/evaluation.py` on the fixed 200-question internal validation partition before training. In one process it retains the model and AdamW state, scans only training questions, stores each selected group's three JSONL stages, applies guarded optimizer updates, and saves a checkpoint after each update. With `update_epochs: 1`, every update has a fresh rollout from the current policy; with `update_epochs: 2`, the second update on a group reuses its frozen `old_log_probs` and advantages, while recomputing current-policy log probabilities. The step record identifies the rollout policy, data age, and one source trajectory directory. The next group's rollout is generated from the updated weights and receives the next `policy_version`. The runner then repeats the identical greedy validation on the final weights and writes `summary.json` with exact counts. If a scan has no mixed-reward group, or post-update drift exceeds the configured guard before a remaining update, it records an incomplete run and retains prior artifacts. A saved checkpoint has model/tokenizer weights but no optimizer state, so a run cannot resume from the middle. The two-fresh-rollout MPS run is `results/m0/end-to-end-v2/`: strict validation is 9/200 both before and after. The same-rollout two-epoch run is `results/m0/end-to-end-mu2-v1/`: strict validation is 9/200 before and 8/200 after. Both generation paths explicitly disable Transformers' model-default fallback; otherwise a reloaded checkpoint can use different decoding settings than the original in-memory model. No official GSM8K test data was used.
