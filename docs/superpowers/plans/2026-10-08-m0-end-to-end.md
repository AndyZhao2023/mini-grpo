# M0 End-to-End Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One CLI prepares the pinned GSM8K split, runs fresh GRPO rollout/update cycles, and compares the initial and final policies on the fixed internal validation split.

**Architecture:** Keep the existing rollout, verifier, advantage, and guarded optimizer functions. Add a greedy evaluator and a small orchestrator that owns one loaded model, tokenizer, and AdamW optimizer for the entire run. Persist each stage and stop honestly if no mixed-reward group is found.

**Tech Stack:** Python 3.12, PyTorch, Transformers, pinned Hugging Face GSM8K, JSON/JSONL, unittest.

**Spec:** `README.md` M0 acceptance contract and `docs/grpo-dataflow.md`.

## Global Constraints

- Keep the pinned dataset/model revisions, strict `#### <number>` reward, G=4, response mask, and `beta=0` contracts.
- Use only the training partition for rollout/update and only the fixed 200-question internal validation partition for evaluation; do not load the official test split.
- Preserve the existing uncommitted edits in `scripts/train_grpo_smoke.py`, `src/grpo/loss.py`, and `src/rollout/hf_rollout.py`.
- Keep model checkpoints out of Git; write exact config and source hashes into the run record.

## Review Focus

- All-zero training groups must not trigger `optimizer.step()`; save the scan summary and finish with an explicit incomplete status.
- Each update must sample from its current policy, with matching `policy_version` and near-one pre-update ratio.
- Evaluation must be greedy, use the same prompt and verifier before/after training, and exclude validation answers from model input.
- Existing output directories must be rejected before expensive model work to avoid silent overwrite.
- Failure after an earlier update must preserve completed step artifacts and never claim the requested update count was reached.
