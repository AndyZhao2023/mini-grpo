# M6：Math-Verify 能否作答案提取器？

## 结论

**可以用作解析组件，当前不能单独作为训练奖励的可信答案提取器。** 在 M5 已标注的 38 组、152 条回答上，Math-Verify 0.9.0 的默认解析配合“截断弃判、合法末行优先”后，匹配人工可判定候选 **126/127**，只漏 1 条；但它也从人工弃判的 **10/10** 条正常结束回答里提取了数字。只允许答案锚点的保守配置仍在 **2/10** 条弃判回答上给出数字，且只匹配 **55/127** 条已知候选。两种配置均未通过预先固定的准入条件，因此本次没有接入训练。

Math-Verify [官方说明](https://github.com/huggingface/Math-Verify/blob/main/README.md)提供 LaTeX、普通表达式等提取方式，并按模式优先级和出现位置选择匹配；其 `parse()` 返回的是解析结果，不包含“这是不是题目最终答案”的可信度。[0.9.0 的发布信息](https://pypi.org/project/math-verify/0.9.0/)用于固定本次版本。这里的失败是本项目输出中存在中间数字、互相冲突的答案和截断片段，并非断言该库的数学表达式解析错误。

## 固定范围与实现

在查看结果前，提交 `6d9e1b2` 固定了[输入哈希、库版本、三种对照方式和准入条件](../results/m6/math-verify-probe-v1/manifest.json)。输入仅为 M2 已保存的训练分区回答及 M5 的人工[答案证据审计](m5-format-signal-audit-v1.md)。M5 标注不是严格盲审，本次也不是独立泛化测试。没有生成回答、读取官方 test、修改现有严格 verifier 或更新模型。Math-Verify `0.9.0` 与 `antlr4-python3-runtime 4.13.2` 安装在临时虚拟环境，未加入项目的训练依赖。

对照方式：

1. **原始默认解析**：对完整文本直接调用 `parse(text)`，只用于诊断；会处理截断文本。
2. **默认数值 + EOS 门控**：截断直接弃判；合法末行由现有严格 parser 读取；其余正常结束文本调用默认 `parse()`，只接受唯一、有限、实数的解析结果，排除字符串回退和互相冲突的数值。
3. **答案锚点 + EOS 门控**：相同的截断和合法末行规则；其余文本设 `try_extract_without_anchor=False`、`fallback_mode="no_fallback"`、`extraction_mode="first_match"`。Math-Verify 不把普通 `#### 5` 自动视作这种锚点，所以合法末行必须由现有 parser 优先处理。

[试验脚本](../scripts/probe_math_verify.py)核对输入 SHA-256 和包版本，然后按 152 个响应键与人工候选逐条比较；[逐条结果](../results/m6/math-verify-probe-v1/output/rows.jsonl)保留原始解析值、两个门控候选及其比较，[汇总](../results/m6/math-verify-probe-v1/output/summary.json)保留计数。准入条件是：对人工已知候选 **0 个不一致**，且对人工弃判的正常结束回答 **0 次提取**；再报告覆盖率和完整题组数。人工弃判不等于模型答案必错，提取出数字只表示**奖励误判风险**。

| 指标 | 默认数值 + EOS | 答案锚点 + EOS |
|---|---:|---:|
| 与 127 条已知人工候选一致 | **126** | 55 |
| 已知候选漏提 | 1 | 72 |
| 已知候选数值不一致 | 0 | 0 |
| 10 条人工弃判的正常结束回答中仍提取数字 | **10** | 2 |
| 15 条截断回答被门控弃判 | 15 | 15 |
| 四条回答都有提取候选的题组 | 24/38 | 0/38 |
| 四条都与人工候选一致、且正确/错误混合的题组 | 10/38 | 0/38 |

未经 EOS 门控的默认 `parse()` 对 152 条全部返回非空列表；按本试验的数值过滤器，其中 147 条有唯一数值，**15 条截断回答中有 11 条也会被提取出数字**。这正是训练时必须另做完成状态检查的原因。

## 关键反例和下一步

- `train/00407` 的 `sample_index=1` 没有给出年龄答案，只有“3 年后”等中间信息；默认解析仍选出 `3`。
- `train/01536` 的 `sample_index=2` 有 `#### 36`，随后又写出合计 `$38`；人工因前后冲突弃判，默认解析给出 `38`。
- `train/02978` 的 `sample_index=0` 先写 `#### 16`，末尾又写 `#### 12`；默认解析选出与标答相同的 `12`，但前后冲突仍使这条回答不适合自动给正奖励。
- `train/03200` 的 `79 percent` 被解析出相互冲突的 `0.79` 与 `79`，本试验的唯一数值过滤器因此弃判。这说明“漏提 1 条”是保守过滤的结果。

下一步可以把 Math-Verify 放在**可信答案片段之后**：先以独立规则判定完成状态、唯一最终答案位置和冲突，再让 Math-Verify 解析该片段并做数学等价比较；没有可信片段就弃判。M5 的 38 组现已用于选择方向，进一步调规则后须在另一批预先固定的回答上验收，才能决定是否接入奖励。当前结果不能证明训练后的准确率或新奖励的收益。
