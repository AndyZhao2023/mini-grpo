# M3 配对错误归因：严格正确数为何从 2/200 到 12/200

## 范围与方法

这是对已保存输出的只读分析：没有重新生成回答、更新权重或读取官方 test。输入是 [M3 的 200 道固定验证题](../results/m3/warm-start-v1/dataset-split.json)更新前后的 JSONL；这些题来自 GSM8K **train**，但与 M3 实际扫描的训练题和 M0 原验证题隔离。脚本核对运行状态、配置与数据哈希、题目 ID、前后汇总，再用 pinned 标答和原严格 verifier 重判全部 400 条回答。

从 200 对中预先选出两类变化并逐题查看原始文本：10 道 `reward 0 -> 1`，以及 34 道 `missing_final_answer -> incorrect_answer`。人工标注保存原回答中可引用的数值与片段；脚本检查引用存在、覆盖的 ID 精确匹配，并比较标注数值、最终解析值和参考值。**标注是针对这些已选题的解释，不是对其余 156 题的算术正确率估计。**

## 结果

| 变化 | 题数 | 从原始回答可支持的解释 |
|---|---:|---|
| 新增严格正确：原先已有相同正确数值与推导 | 6 | 主要是把已有结果放到合法的最终答案行 |
| 新增严格正确：答案数值改变 | 3 | 不能归为纯格式修复；其中一题最终推导仍有明显错误 |
| 新增严格正确：原先未完成计算 | 1 | 后来完成计算并给出合法最终行 |
| 新增明确错误答案：原先已有相同错误数值 | 14 | 格式变化使原有错误数值被严格 verifier 判定 |
| 新增明确错误答案：数值改变但仍错误 | 14 | 既有答案变化，也有格式变化 |
| 新增明确错误答案：原先没有可靠数值 | 6 | 原回答未完成或无法可靠提取最终候选 |

所以 **2/200 → 12/200 是这批题上严格格式与数值联合变化的结果**。10 道新增正确题此前都以 EOS 结束、却没有合法的最后 `#### <number>` 行；这并不意味着 10 道题原先都不会算。另一方面，34 道题变成可解析的错误最终答案，说明输出格式改善也会暴露错误，并不自动提高答案准确性。

## 可核查的例子与限制

- `gsm8k/main/train/06449`：前后都有 `4 + 2 + 1 = 7 goals`，更新后增加 `#### 7`；这是已算出正确数值后补全格式的例子。
- `gsm8k/main/train/02692`：原回答停在 `x = (5 * 94) - (90 + 98 + 92 + 94)`，更新后算出 `x = 96` 并写 `#### 96`；归为完成计算。
- `gsm8k/main/train/01143`：原回答以 `$50` 结尾却没有合法最终行，更新后写 `#### 50`，但与标答不同；格式修复暴露的是错误值。
- `gsm8k/main/train/03553`：最终 `#### 90` 匹配标答，但回答写的 `120 - (120/4 * 3) = 90` 本身不成立，也漏掉进水量。严格 verifier 只核对最终数值，不能证明推理正确。
- `gsm8k/main/train/02057`：最终 `#### 5` 与 GSM8K 标答相符，但题干说较重的 Jack 再拿石头使双方重量相等，表述与标答的计算方向不一致。此处只报告与数据集标答的一致性，不把它当作独立的物理或推理正确性证据。

这是一次单种子、单个固定 200 题样本的归因；没有提供 M3 在官方 test 上的结果，也不能单凭这些变化断言广泛的数学推理能力提升。下一步若要区分格式能力与算术能力，应预先固定独立题集，并分别统计严格最终答案、人工或程序审查的计算过程，以及无合法最终行时可可靠提取的答案数值。

## 复现

从仓库根目录运行；输出目录必须尚不存在：

```bash
HF_HUB_OFFLINE=1 .venv/bin/python -m scripts.analyze_m3_error_changes \
  --output-dir results/m3/my-error-audit
```

不需要本地检查点，需有 pinned GSM8K train 缓存。输入标注在 [annotations.jsonl](../results/m3/error-audit-v1/annotations.jsonl)；[summary.json](../results/m3/error-audit-v1/output/summary.json)记录计数和输入 SHA-256，[paired.jsonl](../results/m3/error-audit-v1/output/paired.jsonl)保留全部 200 对的分类、原始标注与严格判分。原始回答仍以 [更新前](../results/m3/warm-start-v1/validation-initial.jsonl)和[更新后](../results/m3/warm-start-v1/validation-final.jsonl)文件为准。
