# M0 answer-value audit v1

1. **Outcome.** 对既有 100 道训练分区诊断题的回答做只读审计：在 51 条正常 EOS 结束、但缺少严格 `#### <number>` 末行的回答中，47 条有可辨认的答案数值；15 条数值与标答一致，32 条不一致，4 条无法可靠提取。可辨认的 15 条里，12 条出现在末尾，3 条出现在较早的位置。
2. **Before.** [先前的长度诊断](m0-failure-diagnostic-v1.md)记录了 83 条缺少最终行、其中 32 条截断，但不能判断正常结束的回答是否已经说出正确数值。固定内部验证集的 M0 结果仍为 9/200 → 9/200。
3. **Why (Inferred).** 用户选择先调查答案质量，再考虑 rollout 后端；需要知道只修复最终行格式能覆盖多少可观察错误。
4. **Core intuition.** 严格 reward 为 0 的回答，可能已经给出正确数字，也可能给出错误数字。先仅依据题目和生成文本写入候选数值及原文证据，再用固定版本的 GSM8K 标答比较。比较的是**候选数值**，并非推理过程是否正确。
5. **Flow.** `train/06046` 正常结束、没有 `####`，回答写出“Ellen has 832 calories left for dinner.”；标注候选 `832`，与标答 `832` 相同，严格 reward 仍为 0。`train/03430` 的末尾 `520` 与标答 `70` 不同，补一个 `####` 也不会让该回答正确。`train/05286` 在回答中写了 `#### 33`，之后又输出提示语，因此正确数字没有处于要求的最后一行。
6. **Explained change.** 新增的人工候选表只读原有生成文本；[脚本](../scripts/audit_m0_answers.py)校验该表覆盖全部 51 条目标回答、每条证据确实出现在原文、数字出现在证据里，再跨到固定版本的数据集标答做 Decimal 比较。[标注](../results/m0/answer-audit-v1/annotations.jsonl)、[逐题比较](../results/m0/answer-audit-v1/audit.jsonl)和[汇总](../results/m0/answer-audit-v1/summary.json)分别保存这三个阶段。没有重新生成回答或更新模型。
7. **Invariants and boundaries.** 输入必须与原诊断的 100 个有序 prompt ID 和数据 SHA-256 一致，且属于训练分区；不读取内部验证集或官方 test 的回答。`terminal` 表示末尾有明确数值；`nonterminal` 表示更早出现明确数值、但末尾无有效答案；`unresolved` 表示没有单一可信候选。32 条截断的缺失答案不进入本轮候选比较。15/51 是这批已选训练题中人工提取候选与标答的一致数，不是新的 held-out 准确率，也不是数学推理正确率。
8. **Failure and recovery.** 候选表缺项、重复 ID、虚构原文证据、数字不在证据中或输入清单不匹配时，脚本会在写汇总前报错。输出文件以独占创建方式写入；若运行中断，检查是否已有部分输出，并在新目录重跑。人工提取存在主观判断，审阅者可以根据保存的原文和证据复核或另做独立标注。
9. **Evidence.** 本地运行 `HF_HUB_OFFLINE=1 .venv/bin/python -m scripts.audit_m0_answers` 得到 51 条逐题比较：`terminal=42`、`nonterminal=5`、`unresolved=4`；`matches_reference=15`、`different_from_reference=32`、`unresolved=4`。输入文件哈希写入汇总。相关单元测试见 [test_audit_m0_answers.py](../tests/test_audit_m0_answers.py)。
10. **Comprehension check.** 见下方五个问题。下一步的受控质量实验应依据这一结果设计：单纯修复已生成文本的格式至多能覆盖这里数值已吻合的回答，不能把 32 条候选数值错误变正确。

## Questions

1. 哪个文件保存参考答案，哪个文件保存生成回答？
2. 为什么 `train/06046` 的严格 reward 为 0，而审计数值与标答相同？
3. 为什么 32 条截断的缺失答案没有被归为“数值错误”？
4. 如果标注证据不在生成文本中，脚本怎样处理，如何重跑？
5. 15 条数值吻合是否意味着这轮模型在 100 道训练题上的准确率为 21%？

## Answers

1. 固定版本的 GSM8K 数据集含参考答案；原诊断的 `evaluation-128.jsonl` 含生成回答。标注表不含参考答案。
2. 严格 verifier 只接受最后一个非空行完整匹配 `#### <number>`；这条回答以普通句子结束。
3. 它们尚未正常完成，当前片段中的数值可能只是中间结果；本轮仅比较正常 EOS 结束的缺失最终行回答。
4. 脚本抛出 `ValueError`，不产出完整汇总；修正标注后在新的输出目录运行，或先处理上次的部分输出。
5. 不能。15 条来自人为提取的数值一致性审计，6 条来自严格 verifier；两者口径不同，而且这 100 道题属于训练分区、已用于诊断，不能作为新的 held-out 准确率。

## Open questions

- 人工候选提取需要独立复核，特别是数值出现在中间步骤、回答前后互相矛盾的情况；目前将明显冲突归为 `unresolved`。
- 本审计不能估计改变 prompt、模型或训练后的效果。后续实验需要在预先划出的开发题上只改变一个因素，并保留未用于选择的最终评估题。
